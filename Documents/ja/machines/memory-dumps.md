# メモリダンプ

メモリダンプは、実行中のゲストのメモリとプロセッサの状態を Mac 上のファイルに保存します。LLDB や独自のツールでオフライン解析するためのものです。メモリのコピー中はゲストが一時停止し、その後そのまま動作を続けます。

ダンプには 3 種類あります。

| 種類 | 開始する場所 | 保存されるもの |
| --- | --- | --- |
| カーネルと vCPU のコア | **Diagnostics > Save Memory Dump…** | カーネルの仮想アドレスで見たゲストの RAM、すべての vCPU のレジスタ、Secure Enclave のメモリ |
| 物理メモリイメージ | 同じパネルのチェックボックス | ゲストの RAM 全体を物理アドレスで |
| プロセス単位のダンプ | Processes ウィンドウの **Save Memory Dump…** | 1 つのプロセスの常駐メモリを、そのプロセス自身のアドレスで |

## ダンプを保存する

1. 仮想マシンのウィンドウで **Diagnostics > Save Memory Dump…** を選びます。
2. フォルダを選びます。その中に、`myphone Memory 2026-11-19 at 15.20.11` のようにマシン名と時刻を付けた新しいフォルダが作成されます。
3. ダンプの保存先を知らせるアラートが表示されるまで待ちます。ゲストが一時停止するのは最初の部分だけで、通常 10〜20 秒です。ファイルの書き込み中はゲストが再び動作しており、書き込みにはさらに 1 分ほどかかることがあります。

[一時停止](create-and-run.md#一時停止と再開)したゲストもダンプできます。ゲストは一時停止したままで、ダンプには一時停止した時点のゲストが記録されます。

ダンプの保存中に VM を停止すると、ファイルの書き込みが終わるまで待ってからゲストをシャットダウンします。`vphone-cli vm stop` は 20 秒で待つのをやめてゲストの電源を切り、ダンプもそこで終わります。`--timeout 300` のように長めの `--timeout` を指定してください。

ターミナルからは、マシンの[制御ソケット](create-and-run.md#制御ソケット)に、作成するフォルダを指定して `memory.dump` を送ります。そのフォルダはまだ存在していてはならず、親フォルダは存在している必要があります。

```sh
printf '%s\n' '{"t":"memory.dump","path":"/Users/me/Dumps/myphone-1"}' | nc -U ~/.vphone/machines/myphone/vphone.sock
```

応答はファイルの書き込みが終わってから返ります。各ファイルのサイズと実際に保持しているバイト数、キャプチャと書き込みにかかった時間が含まれます。`vphone-launchpad-cli guest send` は 2 分で待つのをやめるため、8 GB の書き込みにそれ以上かかる Mac では上のように `nc` を使ってください。

## ダンプの内容

| ファイル | 内容 |
| --- | --- |
| `AP.core` | カーネルの仮想アドレスで見たゲストの RAM、vCPU 上で実行中だったプロセスのユーザメモリ、すべての vCPU の汎用レジスタ |
| `SEP-coproc.core` | Secure Enclave のメモリ（約 20 MB） |
| `info.json` | マシン、時刻、vphone と macOS のバージョン、各ファイルのサイズ |

どちらのコアも Mach-O のコアファイルです。LLDB は `AP.core` をそのまま開き、vCPU ごとにスレッドを表示します。

```sh
lldb -c "myphone Memory 2026-11-19 at 15.20.11/AP.core"
```

`thread list`、`register read`、`memory read`、`bt` はほかに何も用意せずに使えます。シンボルを使うには、ゲストが起動したカーネルキャッシュを追加し、`target modules load --file <kernelcache> --slide <slide>` でゲストの KASLR スライドにロードします。

ダンプには、物理アドレス、変換テーブルのベースやポインタ認証キーなどのシステムレジスタ、カーネルがマップしていないメモリは含まれません。

## 物理メモリイメージ

Save Memory Dump のパネルで **Physical memory image** を選ぶと、コアの代わりに `physical.elf` を保存します。これは ELF のコアファイルで、ゲストの DRAM 用とその下にあるファームウェアのカーブアウト用に `PT_LOAD` が 1 つずつあり、各セグメントのアドレスはゲストの物理アドレスです。`VPHONE` ノート（タイプ `0x5650`）には、マシン、ゲストのカーネル、その物理アドレス、ページテーブルのルートを記した JSON が入っています。物理メモリを読むツールで使ったり、ゲストのページテーブルを自分でたどってアドレスを変換したりするのに使えます。

ゲストが一度も使っていないページはファイルから省かれます。イメージ全体を書き終えるまでゲストは一時停止したままで、Mac のメモリに余裕があれば通常 10〜20 秒です。

ターミナルからは、`memory.dump` に `"physical":true` を加えます。

```sh
printf '%s\n' '{"t":"memory.dump","path":"/Users/me/Dumps/myphone-2","physical":true}' | nc -U ~/.vphone/machines/myphone/vphone.sock
```

## プロセス単位のダンプ

1. **Diagnostics > Processes** を選び、プロセスを 1 つ選択します。
2. ツールバーまたはコンテキストメニューで **Save Memory Dump…** を選び、フォルダを選びます。新しいフォルダには、`myphone SpringBoard (36) Memory 2026-11-20 at 10.02.03` のようにマシン名、プロセス名、pid が付きます。

vphone はゲストの助けを借りずに、Mac 側からプロセスのメモリを読みます。Virtualization のカーネルデバッグスタブから読んだ vCPU の 2 つのレジスタでゲストのカーネルを見つけ、プロセスリストをたどってその pid を探し、プロセスのページテーブルがマップしているページをすべてコピーします。この間ゲストは一時停止し、通常は数秒です。vphoned が提供するのは、選択元のプロセスリストだけです。保存する時点でその pid が別のプロセスのものになっていた場合、ダンプは中止されます。リストを更新してからやり直してください。

フォルダには、プロセス名を付けた Mach-O のコアと `info.json` が入ります。LLDB はコアを開き、その中の dyld のデータからプロセスのイメージを見つけます。

```sh
lldb -c "myphone SpringBoard (36) Memory 2026-11-20 at 10.02.03/SpringBoard.core"
(lldb) image list
(lldb) memory read 0x104218000
```

コアに含まれるのは、プロセスの常駐ページだけです。一度も触れていないページ、ゲストが圧縮またはページアウトしたページ、スレッドとレジスタは含まれません。各セグメントのアクセス権はページテーブルのエントリから取っています。

ターミナルからは、pid を指定して `process.dump` を送ります。`name` は省略可能で、指定した場合はプロセスがその名前でなければダンプは中止されます。

```sh
printf '%s\n' '{"t":"process.dump","pid":36,"name":"SpringBoard","path":"/Users/me/Dumps/springboard"}' | nc -U ~/.vphone/machines/myphone/vphone.sock
```

プロセス単位のダンプは、vphone に同梱されたカーネルキャッシュのレシピ（iOS 18.1〜27.2）のいずれかのカーネルで動くゲストに対応しています。vphone はそのカーネルのシンボルマップから 2 つのアドレスを使います。それ以外のカーネルでは、カーネルが不明である旨を返します。

## 容量と時間

- `AP.core` はゲストの RAM より少し大きく、8 GB のゲストでは 8.6 GB です。すべてゼロのブロックはファイルから省かれるため、APFS ボリュームではデータ分の容量しか使いません。通常はゲストの RAM の大部分です。
- ボリュームの空き容量がゲストの RAM より少し多い量に満たない場合、ゲストを一時停止する前に保存を中止します。プロセス単位のダンプでは、書き込みうる最大量であるゲストの RAM の 2 倍（最低 4 GB）を求めます。
- ゲストの一時停止中、macOS はそのメモリのコピーを保持します。メモリに余裕のない Mac では、一時停止と書き込みに時間がかかります。
- 一時停止中はゲストの時計が止まります。ゲストが再び動き出すとすぐに、`vphone-vm` がゲストの時計を Mac の時刻に戻します。
- 1 台のマシンについて、同時に保存できるダンプは 1 つです。

カーネルと vCPU のコアには、Virtualization フレームワークがメモリコアを書き出せる macOS が必要です。macOS 27.2 は対応しています。対応していない macOS ではメニュー項目が使用できず、`memory.dump` はその旨を返します。物理メモリイメージとプロセス単位のダンプは、仮想マシンを実行する Virtualization のプロセスからゲストの RAM を読むため、System Integrity Protection のデバッグ制限をオフにしておく必要があります。これは [ホストの設定](../get-started/host-setup.md) ですでに求めている設定です。

ダンプの作成方法と測定結果については、[`Research/Host/memory_dump.md`](../../../Research/Host/memory_dump.md) と [`Research/Host/process_memory_dump.md`](../../../Research/Host/process_memory_dump.md) をご覧ください。
