# CVE-2026-86916: где сайт бага и применим ли он к 23F84

Дата: 2026-11-26. Цель: проверить последний непроверенный kernel-кандидат для iPhone 13 (26.5.2 / 23F84) — «IGMP UAF» CVE-2026-86916 в связке с `getsourcefilter` (чтение кучи) и `setsockopt(ICMP6_FILTER)` (запись) из `ios26-kernel-research/chain-design.md`.

## Что установлено

1. **Advisory (support.apple.com/en-us/149034 и 149035, 26.10.2026).** Компонент — «Kernel», тип — «use after free … improved memory management», автор Wang Yu, impacto — «app may be able to execute arbitrary code with kernel privileges». Закрыт в **iOS 26.7 / 27.0** (не в 26.6.1, как было записано в `chain-design.md`). Публичного PoC нет (GitHub-поиск по номеру — 0 репозиториев); функция не названа.
   → iPhone 13 (26.5.2) формально уязвим; 17 Pro Max (27.2.1) — нет.

2. **Привязка к IGMP не подтверждается.** Открытый XNU (`apple-oss-distributions/xnu`, теги `xnu-11417.101.15` ≈ 26.5.0 и `xnu-11417.140.69` ≈ 26.6.x): `bsd/netinet/igmp.c`, `in_mcast.c`, `bsd/netinet6/in6_mcast.c`, `mld6.c` — **не изменились ни на байт** (md5 одинаковые). Изменения между поколениями (11417 → 12377) в этих файлах — косметика (`os_atomic_cmpxchg` для `igmp_initialized`, `ifnet_is_fully_attached`), не UAF-фикс.

3. **Бинарный дифф kernelcache 23F84 vs 24B156** (`tools/kdiff.py`, `tools/fdump.py`, capstone 5 в `/tmp/jbresearch/venv`):
   - `igmp_input_v3_query` (23F84 `0xfffffff00a17800c`, 24B156 `0xfffffe000afb371c`): 607 vs 604 инструкции; расхождения — только генерация кода (на A19 clang сплавил `cmp+csel` в инструкции, которые capstone 5 не декодит, и перераспределил регистры). `casl w2,wzr,[x21]` → `b.ne` → `bl` → `casa x8,x9,[x21]` на `+0x570/+0x584/+0x590` присутствует в обоих билдах. Утверждение `chain-design.md` «CAS-unlock removed at handler+0x0584» бинарно не подтверждается: на `+0x584` в обоих билдах стоит `bl`.
   - `inm_remref` (23F84 `0xfffffff00a1879a8`, 24B156 `0xfffffe000afc3bcc`): 373 инструкции, **ноль** расхождений, все 14 атомик на своих местах.
   - `in_multi_detach` (23F84 `0xfffffff00a189d0c`, 24B156 `0xfffffe000afc5990`): 119 инструкций идентичны.
   Дизассемблирование: `ios26-kernel-research/igmp_v3_query_23F84.dis`, `…_24B156.dis`.

## Вывод

- Сайт CVE-2026-86916 не находится ни в открытых исходниках, ни в трёх главных мультикаст-функциях; без знания сайта триггерить нечего. Фаззинг мультикаста на 26.6.1 (21M операций, 0 аномалий) уже выполнялся автором `ios26-kernel-research`.
- Для цели (jailbreak 23F84 / 24B156) направление закрыто: даже при наличии UAF в ядре 23F84 связка требует примитивов `getsourcefilter`/`ICMP6_FILTER` из того же исследования, а они не переносимы без точного сайта и слайда KASLR.
- Инструменты `kdiff.py`/`fdump.py`/`funclist.py` (строковый якорь → xref → функция → нормализованный дифф) пригодятся для проверки следующих CVE, где функция известна.

## Что осталось открытым

- Точная функция CVE-2026-86916 — только через KDK-дифф (macOS 15.7.x → 15.8, 26.6 → 26.7.2) или отчёт Wang Yu; см. `05_…md`, п. 4 (закрыт) и добавленный п. 8.

Что это меняет:

- **CVE-2026-86916 остаётся открытым kernel-кандидатом для 23F84** (UAF, «execute arbitrary code with kernel privileges», fix в 26.7). Сайт бага по-прежнему не локализован. Вопрос 8 в `05_open_questions_and_next.md` (KDK-дифф macOS 26.6 → 26.7.2) возвращается в список открытых.
- Привязка к IGMP **по-прежнему опровергнута** отдельным бинарным сравнением 23F84 ↔ 24B156 (`igmp_input_v3_query` CAS-unlock на +0x570 в обоих билдах); смена компонента в таблице на неё не влияет.
- `CVE-2026-86962` — «double free», а не UAF с повышением привилегий; «execute arbitrary code with kernel privileges» относится к `86916`.
- `CVE-2026-65343`: по адвизори это **Kernel** («a remote attacker may be able to cause unexpected system termination», UAF, fix 26.6.1). Заметка `08_applekeystore_cve_65343.md` и `poc-survey.md` приписывают его `AppleKeyStore` (по репозиторию ByteV0rtex). Это противоречие в источниках; локальная проверка AppleKeyStore закрыта (ACM-хэндл не получить), но как kernel-CVE `65343` в каталог кандидатов **не попадал** и его надо проверить отдельно.

### (снято) Поправка 2026-11-26 (вечер): CVE-2026-86916 — не kernel UAF

Проверено по первоисточнику — адвизори Apple (локальные копии в `/tmp/jbresearch/advisories/`,
разбор в `ios26-kernel-research/apple_advisory_entries_26.5.2_to_27.2.1.md`):

| Адвизори | Компонент | Impact | Fix |
|---|---|---|---|
| iOS 26.7 (`https://support.apple.com/en-us/149041`) | **libarchive** | Processing a maliciously crafted file may lead to unexpected app termination | A heap buffer overflow was addressed with improved bounds checking |
| iOS 27 / iPadOS 27 (`https://support.apple.com/en-us/149034`) | Kernel | A remote attacker may be able to bypass firewall rules | This is a vulnerability in open source code and Apple Software is among the affected projects. The CVE-ID was assigned by a third party |

Вывод: запись «Kernel UAF (Wang Yu)» в `04_public_exploit_landscape.md` и в `chain-design.md` неверна.
Это heap overflow в libarchive (терминация приложения) либо обход правил файрвола в сетевом коде.
Для джейлбрейка iPhone 13 как примитив памяти ядра — **закрыто**; KDK-дифф для этой CVE не нужен
(п. 8 в `05_open_questions_and_next.md` снимается). В адвизори iOS 26.5.2 её нет.

Заодно исправлено рядом:
- **CVE-2026-64788** — это `IOMobileFrameBuffer`, OOB («unexpected system termination or corrupt kernel memory»), закрыт в **iOS 26.6.1**. Не IOGPUFamily. На 23F84 (26.5.2) формально открыта.
- **CVE-2026-65346** — `IOGPUFamily`, «improved memory handling», impact через вредоносный веб-контент, iOS 26.6.1. **CVE-2026-86944** — `IOGPUFamily`, race, iOS 26.7. На 26.5.2 открыты обе.
- **CVE-2026-43743** (запись «IOGPU race» в `04`) закрыт уже в **iOS 26.5.2** → на iPhone 13 его нет.
- **CVE-2026-43655** отсутствует во всех шести адвизори (26.5.2 … 27.2.1) → описание «IOSurfaceAccelerator OOB read, fixed 26.7» не подтверждено.
