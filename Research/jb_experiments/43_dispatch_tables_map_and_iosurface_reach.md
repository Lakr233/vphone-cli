# 43. Карта таблиц внешних методов на 23F84; `IOSurfaceRootUserClient` и FastPath `open` вызваны из sandbox

Дата: 2026-11-27. Устройство: iPhone 13 (A15, 26.5.2 / 23F84). Статика: `tools/kdiff2/kdisp.py` по тому же kernelcache.
Пробники: `tools/iosurf_probe/` (bundle `me.strelov.iosurf`), `tools/hid_fastpath/` (`me.strelov.hiddev`); только get-task-allow, песочница по умолчанию.
Исходящие соединения с устройства не делались.

Зачем: после того как заработало декодирование указателей (`kcptr.py`, `kstarts.py`), таблицы `IOExternalMethodDispatch2022` ищутся напрямую — по форме записи. Это снимает блокировку «vtable не получена» из заметок 27/34 и даёт точные счётчики аргументов для каждого селектора.

Устройство не паниковало ни в одном прогоне.

### `IOSurfaceRootUserClient`: селекторы со структурой любого размера на входе

Сел. 0, 9, 10, 11, 19, 24, 26, 46, 47, 48, 50, 51, 54 (и их зеркала 60, 69, 70, 71, 79, 84…). Функции: `0x98b1398`, `0x98b1630`, `0x98b1744`, `0x98b1924`, `0x98b1b48`, `0x98b1cf8`, `0x98b1e4c`, `0x98b23b8`, `0x98b24ec`, `0x98b2600`, `0x98b27bc`, `0x98b27f0`, `0x98b2860`.

### `copyEvent` FastPath (сел. 2 → `0x966f694`): что видно в коде

- Скаляр[0] клиента (`x22`) сравнивается беззнаково с `провайдер->vtable+0x140() − 4`; больше — ошибка `0xe00002be + 0x1d`.
- Затем `str w22,[x0]` в объект от `vtable+0x148` и вызов `[dict vtable+0xe8](dict, x0+4, x22)`.
- При `n < 4` предел `n − 4` беззнаково огромен, проверка не работает. **Может ли провайдер вернуть `n < 4` — не установлено.**

## Что из этого следует

- Из sandbox на 23F84 теперь две открытые и не дочитанные поверхности: `IOSurfaceRootUserClient` (120 селекторов) и FastPath `copyEvent`.
- Заметка 41 (соседний тред) разбирает `IOSurface` по диффу 23F84 → 23G83 и отмечает досягаемость как непроверенную живьём; здесь она подтверждена.
- Для соседних заметок (27, 34) выводы вида «таблица не получена» устарели: инструмент есть.

## Не получилось

- `copyEvent` живьём не вызывался: формат входного словаря не известен, вызов с произвольным индексом на ядре без этого не делался.
- `IOSurface`: селекторы 0 и 4 вернули `BadArgument` уже от метода — нужные аргументы не подобраны.
- Не разобрано, какой класс возвращает `vtable+0x140` у `AppleSPUHIDDriver` и каким бывает `n`.
- Ложные срабатывания `kdisp.py`: одиночные записи в vtable; отфильтрованы порогом «≥3 селекторов».
