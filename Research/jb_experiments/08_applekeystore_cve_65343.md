# AppleKeyStore / CVE-2026-65343 на iPhone 13 (26.5.2) и 17 Pro Max (27.2.1)

Дата: 2026-11-26. Пробник `tools/aksprobe.m` — по схеме `ByteV0rtex/CVE-2026-65343/poc/poc_aks_oob.m`: прямое открытие `AppleKeyStore`, попытка захватить реальный ACM-хэндл через interpose `IOConnectCallMethod` при SE-подписи, затем replay по селекторам 1–163 с `struct_in` 28 байт (`[0..15] handle, [24..27] declared_length = 0x800`), вывод 0x2000 с заполнителем `0xBB`. Сырые логи — `aks_13.txt`, `aks_17.txt`.

## Результат

| | iPhone 13, 26.5.2 | iPhone 17 Pro Max, 27.2.1 |
|---|---|---|
| `IOServiceOpen("AppleKeyStore", type 0)` | `kr=0` | `kr=0` |
| SE-ключ P-256 + подпись | ок | ок |
| Захвачен `IOConnectCallMethod` в процессе | **нет** | **нет** |
| Селекторы, вернувшие `kr=0` | 1, 16 — вывод пустой (`nonfill=0`) | то же |
| `0xe00002c1` NotPermitted (sandbox на селекторе) | 21 диапазон | 21 |
| `0xe00002c2` InvalidArgument (неверный формат/хэндл) | 22 | 23 |
| `0xe00002e2` NotPrivileged | 1 (sel 19) | 1 (sel 19) |
| `0xe00002e6` | — | 1 (sel 54) |
| Указателей ядра в выводе | **0** | **0** |

Распределение кодов по номерам селекторов **не отличается** между устройствами (diff пустой; на 17PM иначе обработаны лишь границы диапазонов sel 99/100 и добавлен sel 163).

## Вывод

- **`AppleKeyStore` из app sandbox открывается**, но полезные селекторы разделены на «sandbox запрещает» (`NotPermitted`) и «неверный аргумент» (`InvalidArgument`). Уязвимый путь `_LibSer_SEPControl_Deserialize` требует валидный ACM-хэндл — без него все они попадают во вторую группу, и на 26.5.2 поведение не отличается от 27.2.1, где CVE закрыт.
- Захватить ACM-хэндл в процессе не получается: `Security.framework` на iOS 26/27 уходит по XPC в `ctkd`, в процессе нет вызовов `IOConnectCallMethod`. Это совпадает с указанием PoC: **нужен sandbox escape**, после которого открываются и селекторы, и настоящий хэндл.
- То есть для использования как KASLR-bypass этот CVE стоит **после** sandbox escape, а не до. С `worse_query` (userland, без выдачи прав на IOKit-селекторы) он не связан — `worse_query` даёт токены на пути файловой системы, не на IOKit.

## Что не проверено

- Селекторы с «настоящим» хэндлом — нечем получить без escape; проверка возможна только из root-контекста (на Basil через `vphoned` — но там CVE закрыт, 27.2).
- Селекторы за пределами 1–163.
