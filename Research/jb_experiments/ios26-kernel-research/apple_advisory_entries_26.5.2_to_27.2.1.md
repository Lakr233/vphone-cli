# Apple advisories iOS 26.5.2 → 27.2.1: entries rebuilt by `<h3>` component heading (2026-11-27)

Источник: локальные копии `/tmp/jbresearch/advisories/adv_*.html` (support.apple.com отдаёт 429 после нескольких запросов). Индекс: <https://support.apple.com/en-us/100100>. Машиночитаемо: `entries_by_heading.json`, `cve_index.json` (та же папка).

**Почему старая версия была неверна.** На странице Apple заголовок компонента — `<h3>`, он стоит *перед* блоком записи, а строка `CVE-…: credit` — *последняя* строка блока. Старый парсер брал слово перед `Available for:` (хвост кредита предыдущей записи) и описание соседнего блока: компоненты были сдвинуты на одну запись, а часть описаний (`86962` → «null pointer dereference», «execute arbitrary code with kernel privileges») вообще взяты из чужих блоков. Эта версия собрана по `<h3>` и по `Impact`/`Description` того же блока.

**Сводка.** iOS 26.5.2: 30 blocks / 36 CVE items / 3 Kernel; iOS 26.6: 88 blocks / 94 CVE items / 18 Kernel; iOS 26.6.1: 26 blocks / 35 CVE items / 3 Kernel; iOS 26.7: 92 blocks / 94 CVE items / 18 Kernel; iOS 27: 157 blocks / 161 CVE items / 22 Kernel; iOS 27.2.1: 9 blocks / 8 CVE items / 0 Kernel

## 5. Правила чтения адвизори (для агентов)

- Компонент — ближайший `<h3>` *выше* строки CVE, а не слово перед `Available for:`.
- Один блок может содержать несколько CVE (например `CVE-2026-43739 CVE-2026-43816` в 26.6); все они относятся к одному компоненту и описанию.
- `Entry added/updated <date>` — служебная пометка Apple, не часть описания.
- Признак «CVE закрыт на 23F84»: отсутствие в списках 26.6 / 26.6.1 / 26.7 / 27 (при условии, что CVE вообще есть на этих страницах).
